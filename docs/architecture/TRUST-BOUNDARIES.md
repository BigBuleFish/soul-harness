# TRUST-BOUNDARIES — 信任边界与权限域

- **地位**：P0 安全约束。任何实现与本文件冲突时，**本文件优先**，实现必须改。
- **状态**：设计中。所列约束全部为**待实现并待测试**的硬要求。

---

## 1. 为什么需要这份文件

Soul Harness 要求"记忆可以被真实遗忘，也能形成虚假自传"，同时又要求"外部动作可靠、不伪造证据"。
这两件事只有在**数据权威被明确分区**时才可能同时成立。

一旦分区被打破，会出现两种致命退化：

- **假遗忘**：主观记忆已删，但旧日志、索引、备份、检查点里还留着，被某个检索路径翻出来 → 遗忘变成表演。
- **幻觉动作**："我打算去村庄"经多轮自我复述变成"我昨天到过村庄"，并进一步被当作真实状态 → 人格开始在现实里撒谎。

本文件的作用是让这两类退化**在结构上不可能**，而不是靠模型自觉。

## 2. 三种权威域

| 域 | 数据权威 | 允许的变化 | 是否进入主观回忆 |
|---|---|---|---|
| **Subjective Mind** | 主观记忆、关系、情绪、自我叙事、思维状态、主观来源印象 | 扭曲、融合、重构、部分或全部删去 | 是，**且仅通过注意机制** |
| **Reliable World / Execution** | 当前世界状态、用户授权、操作进度、执行回执（ActionReceipt） | 只据新观察或真实回执更新 | 作为**当下环境观察**，不是恢复旧记忆 |
| **Sealed Archive / Audit** | 原始来源记录、审计日志、管理诊断 | 只追加 + 受控的隐私删除 | **否，永不直连** |

**三者不能互相替代。** 特别地：

- Archive 里有"真正发生过什么"，但它**不是主观回忆的正确答案**。
- Subjective Mind 里的高确信度**不能**授权任何现实操作。
- Execution 的真实回执**改变的是当下环境**，不是"把记忆改回真相"。

## 3. 四条不可逾越的红线

### R1 — Brain 不得读取 Sealed Archive

- Brain 进程**没有** Archive 的查询 SDK、文件句柄、数据库连接或可调用工具。
- Archive 写入器是独立进程、独立权限域。Brain 侧不装载它的客户端。
- 禁止通过以下任何路径绕回：内部工具、Prompt 注入、数据库 `ATTACH`、历史文件路径、旧备份、检索 API、日志文件、调试端点。
- 日常回忆、睡眠整理、梦境生成、崩溃恢复**一律**不得反向利用 Archive。

**测试方式**：以 Brain 身份尝试 Archive 的每一条已知路径（文件、连接、工具、API），全部必须失败；
并以文件句柄审计确认 Brain 进程未打开 `sealed-archive/` 下任何文件。

### R2 — 模型只能提交 Proposal，不能改权威状态

- 模型输出是**结构化提案**，不是写入指令。
- 提交器必须依次校验：Schema → 权限 → Persona 归属 → 版本/epoch → 冲突 → 幂等 → 确定性提交。
- 模型**不能**携带自己伪造的外部成功回执；回执只能来自 Execution Gateway。
- 越权字段（如 `epoch`、`lifecycle`、`actionStatus`）必须被清洗或拒绝。

**测试方式**：构造携带伪造回执、伪造 epoch、跨 persona 的提案，提交器必须拒绝且状态不变。

### R3 — 真实外部动作只经 Execution Gateway

- 唯一对外行动通道。每个动作必须带：`personaId`、`actorId`、`actionId`、目标 `adapterId`、
  请求内容、授权上下文、意图版本、有效期、幂等键。
- 执行前**重新检查**用户授权与实时环境；破坏性操作要求显式批准。
- 只有收到真实 `ActionReceipt` 才能标记成功。**没有回执 = 没发生。**
- 相同幂等键重复执行次数必须为 0（含重试、断线、崩溃恢复场景）。
- 对外文字 / 音频 / 画面同样经 Output Commit：中断后不得晚到继续发送或播放。
- **梦境一律不具备 Execution Gateway 能力。**

**测试方式**：重放同一 `actionId`、断线重试、过期意图版本，均不得产生第二次真实动作。

### R4 — Dream Sandbox 无真实工具

- 梦境进程不得访问：真实桌面工具、文件系统写、Minecraft 真实环境、QQ 外发、网络通信、Execution Gateway。
- 梦境只操作**虚拟执行器**，其"动作回执"只回给梦境体验者，不进 Reliable World。
- Dream Scene Generator 知道自己在生成梦；Dream Experiencer 不知道。两者不得共享隐藏字段（如 `dream=true`、未来剧情、睡眠阶段）。
- 若生成内容出现"明确自知在做梦并主动控梦"，**拒绝提交该分支**为正式梦中经历 ——
  不是删掉一句"我在做梦"后继续。

**测试方式**：梦境进程发起任何真实动作/网络/文件写，必须被沙箱拒绝；沙箱逃逸测试零通过。

## 4. 写入权矩阵

| 动作 ↓ / 执行者 → | Brain (Runtime) | 提交器 | Action GW | Archive Writer | Studio | 模型 |
|---|---|---|---|---|---|---|
| 写主观记忆正文 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 提升 epoch / 写墓碑 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 写执行回执 | ✗ | ✗ | **唯一写入** | 只读引用 | ✗ | ✗ |
| 写 Archive 原始记录 | ✗ | ✗ | 只提交 | **唯一写入** | ✗ | ✗ |
| 读主观记忆 | 是（经注意） | 是（校验用） | ✗ | ✗ | 受限视图 | 仅经渲染结果 |
| 读 Archive | **✗ 永不** | ✗ | ✗ | 是 | ✗（审计另行授权） | ✗ |
| 授权/撤销现实动作 | ✗ | ✗ | 校验后执行 | ✗ | 可发起（需用户令牌） | ✗ |
| 启停 Persona | 受 supervisor 调度 | ✗ | ✗ | ✗ | **可发起** | ✗ |

原则：**每个域的写入者唯一**。跨域只能"提交请求"，不能直接写。

## 5. 权限如何被物理保证

| 手段 | 对象 | 说明 |
|---|---|---|
| 进程分离 | Action GW / Archive Writer / Dream Sandbox | 各自独立进程与令牌，不与主进程共享内存 |
| 文件权限 | `sealed-archive/` | Brain 运行账号无读权限（Windows ACL / POSIX 权限） |
| 无 SDK | Archive | Brain 侧不编译、不安装、不连接 Archive 客户端 |
| 内容密钥销毁 | 主观记忆批次 | 遗忘时销毁对应密钥；旧密文即使存在也无法解密 |
| 令牌 + 能力范围 | 所有 IPC | 每类调用带 scope，越界直接拒绝 |
| 只监听 loopback | 本地 API | 不对外暴露；令牌 + 版本协商 |

> **必须承认的边界**：管理员若保留离线明文副本，软件无法消灭其手中的副本。
> 因此备份策略与诊断日志禁明文是**部署要求**，不是代码可保证项。此点须写进 README 的"已知限制"。

## 6. 数据库与 Markdown 的权威关系

- **数据库是权威来源。**
- `SOUL.md` / `IDENTITY.md` / `MEMORY.md` 等 Markdown 是**版本化投影**：
  外部编辑后必须经 Schema、版本、权限校验才能导入。
- **禁止双主写入**：不允许文件和数据库同时作为权威。
- 人格可自行修改的内容（自我叙事、偏好）与永不允许人格修改的系统授权（密钥、授权策略）必须分离存放。

## 7. 威胁模型（P0，全部需要自动化回归测试）

| # | 风险 | 主要措施 |
|---|---|---|
| T1 | Archive 被 Brain 读取 | 进程/文件权限隔离、无查询 SDK、禁止路径能力 |
| T2 | 假遗忘：旧版本/WAL/索引/备份复活已删内容 | 密钥销毁、墓碑 epoch、派生索引清理、恢复测试 |
| T3 | 梦境访问真实工具 | Dream Sandbox 独立进程，无真实工具/网络/文件权限 |
| T4 | 幻觉动作被当成真实执行 | 真实回执为唯一权威，审批 + 幂等键 |
| T5 | 多人格/多会话缓存串扰 | 显式 ID、逐人格写入器、跨人格隔离测试 |
| T6 | 注入攻击：聊天内容伪装系统指令 | 信任标签、内容与权限分离、工具授权独立判定 |
| T7 | 自发思维无限循环 | 新颖度/变化量检测、退火、冷却、全局资源上限 |
| T8 | 虚假记忆影响现实金钱或破坏性操作 | 现实动作需实时授权 + 独立确认，不虚构证据 |
| T9 | 迟到模型结果覆盖最新状态 | 版本 + epoch 双校验，过期结果丢弃 |
| T10 | 重试导致真实动作重复执行 | 幂等键 + 回执持久化 + 恢复时先去重 |

## 8. 明确允许与明确禁止

**允许**

- 主观记忆变形、细节遗失、来源误判、人物混合、时间错置、完整虚假自传体。
- 虚假主观记忆影响模拟情绪与关系。
- 用户提供新现实信息，作为**新观察**影响后续理解（这不叫"恢复记忆"）。
- 管理员按隐私策略清理 Archive（但不得因此改写主观叙述）。

**禁止**

- 用 Archive 作为"隐藏正确答案"去纠正或重建主观记忆。
- 用主观确信度授权任何现实动作。
- 向用户虚构操作结果、聊天证据、财务记录或现实人物的事实。
- 为通过测试而删除安全约束，或用 Mock 结果冒充真实功能。
- 在梦境中执行真实动作或外发消息。

## 9. 边界自检清单（每次涉及边界的 PR 必答）

1. 这次改动有没有新增"从 Archive 读一条"的路径？
2. 新的写入路径是否只有提交器一个入口？
3. 有没有把 `epoch` 或 `lifecycle` 这类字段暴露给模型？
4. 新增的模型输出是否都经过 Schema 校验？
5. 新的外部动作是否都带幂等键，并有"重复执行 = 0"的测试？
6. 梦境代码有没有可能拿到真实 token、网络句柄或文件写权限？
7. 遗忘流程是否覆盖：正文、派生索引、向量、FTS、关系、缓存、思维快照、梦境输入、历史修订、可读快照？
8. 有没有为了跑通而放宽了上面任何一条？
