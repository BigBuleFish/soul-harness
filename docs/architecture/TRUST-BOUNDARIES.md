# TRUST-BOUNDARIES — 信任边界与权限域

- **地位**：P0 安全约束。任何实现与本文件冲突时，**本文件优先**，实现必须改。
- **状态**：设计中。所列约束全部为**待实现并待测试**的硬要求。

---

## 1. 为什么需要这份文件

Soul Harness 要求"记忆可以被真实遗忘，也能形成虚假自传"，同时又要求"外部动作可靠、不伪造证据"。
这两件事只有在**数据权威被明确分区**时才可能同时成立。

一旦分区被打破，会出现两种致命退化：

- **假遗忘**：主观记忆已删，但旧日志、索引、备份、检查点里还留着，被某个检索路径翻出来 → 遗忘变成表演。
- **幻觉动作**："我打算去村庄"经多轮自我复述变成"我昨天到过村庄"，并进一步被当作真实状态 → 人格开始在现实里撒谎。

本文件的作用是让这两类退化**在结构上不可能**，而不是靠模型自觉。

## 2. 三种权威域

| 域 | 数据权威 | 允许的变化 | 是否进入主观回忆 |
|---|---|---|---|
| **Subjective Mind** | 主观记忆、关系、情绪、自我叙事、思维状态、主观来源印象 | 扭曲、融合、重构、部分或全部删去 | 是，**且仅通过注意机制** |
| **Reliable World / Execution** | 当前世界状态、用户授权、操作进度、执行回执（ActionReceipt） | 只据新观察或真实回执更新 | 作为**当下环境观察**，不是恢复旧记忆 |
| **Sealed Archive / Audit** | 原始来源记录、审计日志、管理诊断 | 只追加 + 受控的隐私删除 | **否，永不直连** |

**三者不能互相替代。** 特别地：

- Archive 里有"真正发生过什么"，但它**不是主观回忆的正确答案**。
- Subjective Mind 里的高确信度**不能**授权任何现实操作。
- Execution 的真实回执**改变的是当下环境**，不是"把记忆改回真相"。

## 3. 四条不可逾越的红线

### R1 — Brain 不得读取 Sealed Archive

- Brain 进程**没有** Archive 的查询 SDK、文件句柄、数据库连接或可调用工具。
- Archive 写入器是独立进程、独立权限域。Brain 侧不装载它的客户端。
- 禁止通过以下任何路径绕回：内部工具、Prompt 注入、数据库 `ATTACH`、历史文件路径、旧备份、检索 API、日志文件、调试端点。
- 日常回忆、睡眠整理、梦境生成、崩溃恢复**一律**不得反向利用 Archive。
- Archive 原始数据**必须加密存储**，不得明文落盘。
- Archive 使用**独立于主观记忆的密钥层级**，**禁止**与主观记忆密钥混用或互相派生。
- Brain **永远不持有** Archive 密钥；解密能力只存在于 Archive Writer 的权限域内。
- **Archive Writer 是唯一原始记录写入者**；其他进程只能提交归档请求，不能直写。
- Archive 拥有**独立的保留与删除策略**，与主观记忆的遗忘流程分开管理。
- **不得**把 Archive 内容导入主观记忆当作"隐藏正确答案"；它只能作为**新观察**从 Ingress 重新进入。

**测试方式**：以 Brain 身份尝试 Archive 的每一条已知路径（文件、连接、工具、API），全部必须失败；
以 Brain 身份尝试解密 Archive 数据必须失败（无密钥）；
并以文件句柄审计确认 Brain 进程未打开 `sealed-archive/` 下任何文件。

### R2 — 模型只能提交 Proposal，不能改权威状态

- 模型输出是**结构化提案**，不是写入指令。
- 提交器必须依次校验：Schema → 权限 → Persona 归属 → 版本/epoch → 冲突 → 幂等 → 确定性提交。
- 模型**不能**携带自己伪造的外部成功回执；回执只能来自 Execution Gateway。
- 越权字段（如 `epoch`、`lifecycle`、`actionStatus`）必须被清洗或拒绝。

**测试方式**：构造携带伪造回执、伪造 epoch、跨 persona 的提案，提交器必须拒绝且状态不变。

### R3 — 真实外部动作只经 Execution Gateway

- 唯一对外行动通道。每个动作必须带：`personaId`、`actorId`、`actionId`、目标 `adapterId`、
  请求内容、授权上下文、意图版本、有效期、幂等键。
- 执行前**重新检查**用户授权与实时环境；破坏性操作要求显式批准。
- 只有收到真实 `ActionReceipt` 才能标记成功。**没有回执 = 没发生。**
- 相同幂等键重复执行次数必须为 0（含重试、断线、崩溃恢复场景）。
- 对外文字 / 音频 / 画面同样经 Output Commit：中断后不得晚到继续发送或播放。
- **梦境一律不具备 Execution Gateway 能力。**

**测试方式**：重放同一 `actionId`、断线重试、过期意图版本，均不得产生第二次真实动作。

### R4 — Dream Sandbox 无真实工具

- 梦境进程不得访问：真实桌面工具、文件系统写、Minecraft 真实环境、QQ 外发、网络通信、Execution Gateway。
- **梦境隔离必须是独立进程**，带独立权限与无网络配置。**Worker Thread 不算隔离**（同进程共享内存与权限）。
- 梦境只操作**虚拟执行器**，其"动作回执"只回给梦境体验者，不进 Reliable World。
- Dream Scene Generator 知道自己在生成梦；Dream Experiencer 不知道。两者不得共享隐藏字段（如 `dream=true`、未来剧情、睡眠阶段）。
- 若生成内容出现"明确自知在做梦并主动控梦"，**拒绝提交该分支**为正式梦中经历 ——
  不是删掉一句"我在做梦"后继续。

**测试方式**：梦境进程发起任何真实动作/网络/文件写，必须被沙箱拒绝；沙箱逃逸测试零通过。

## 4. 写入权矩阵

| 动作 ↓ / 执行者 → | Brain (Runtime) | 提交器 | Action GW | Archive Writer | Studio | 模型 |
|---|---|---|---|---|---|---|
| 写主观记忆正文 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 提升 epoch / 写墓碑 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 写执行回执 | ✗ | ✗ | **唯一写入** | 只读引用 | ✗ | ✗ |
| 写 Archive 原始记录 | ✗ | ✗ | 只提交 | **唯一写入** | ✗ | ✗ |
| 读主观记忆 | 是（经注意） | 是（校验用） | ✗ | ✗ | 受限视图 | 仅经渲染结果 |
| 读 Archive | **✗ 永不** | ✗ | ✗ | 是 | ✗（审计另行授权） | ✗ |
| 授权/撤销现实动作 | ✗ | ✗ | 校验后执行 | ✗ | 可发起（需用户令牌） | ✗ |
| 启停 Persona | 受 supervisor 调度 | ✗ | ✗ | ✗ | **可发起** | ✗ |

原则：**每个域的写入者唯一**。跨域只能"提交请求"，不能直接写。

## 5. 权限如何被保证（分阶段，不得混淆）

### 5.1 当前阶段（P1）的真实状态

> **P1 只有一个 SQLite 文件，三域数据同库、同进程。P1 不具备物理隔离。**
> 此时上表的红线只能靠**接口与代码约束**维持；Brain 进程理论上可直连同一个库文件。

因此 P1 **只允许**运行不产生跨域安全承诺的功能：人格注册、事件接入、状态恢复、最小 API。
**不得**向用户或文档宣称"已隔离"。

### 5.2 需要物理隔离的能力及其启用门槛

| 能力 | 启用前必须满足 | 未达门槛时 |
|---|---|---|
| **Sealed Archive** | 独立 db 文件 + 独立进程 + 独立文件权限（Brain 账号无读权）+ Brain 侧不编译其客户端 + **加密存储 + 独立密钥层级** + 按 `eventId` 幂等 + 句柄审计通过 | **允许接收事件，但不归档**：正文随感知缓冲 TTL 删除，`events.archive_ref` 恒为 NULL，**不承诺原始事件审计能力**（见 `RUNTIME-LIFECYCLE.md` §7.2） |
| **Action Gateway** | 独立进程 + 独立能力令牌 + 幂等键持久化 + 回执校验 + "重复执行 = 0"测试 | 不启用任何真实外部动作 |
| **Dream Sandbox** | **独立进程**（不是 Worker Thread）+ 无网络 + 无文件写 + 无真实工具令牌 + 逃逸测试通过 | 不启用梦境 |

> ⚠ **Worker Thread 不构成安全边界。** 它与主线程同进程、共享内存与权限，只能用于非安全目的的数值计算。
> 任何"用 Worker 隔离梦境"的设计一律驳回。

### 5.3 门槛达成后的物理手段

| 手段 | 对象 | 说明 |
|---|---|---|
| 进程分离 | Action GW / Archive Writer / Dream Sandbox | 各自独立进程与令牌，不与主进程共享内存 |
| 文件权限 | `sealed-archive/` | Brain 运行账号无读权限（Windows ACL / POSIX 权限） |
| 无 SDK | Archive | Brain 侧不编译、不安装、不连接 Archive 客户端 |
| 内容密钥销毁 | 主观记忆批次 | 遗忘时销毁对应密钥；旧密文即使存在也无法解密 |
| 令牌 + 能力范围 | 所有 IPC | 每类调用带 scope，越界直接拒绝 |
| 只监听 loopback | 本地 API | 不对外暴露；令牌 + 版本协商 |

> **必须承认的边界**：管理员若保留离线明文副本，软件无法消灭其手中的副本。
> 因此备份策略与诊断日志禁明文是**部署要求**，不是代码可保证项。此点须写进 README 的"已知限制"。

### 5.4 Archive 存储语义（与主观记忆的边界）

Archive 是**记录域**，不是记忆域。二者在密钥、写入者、保留策略、可访问性上**完全分离**：

| 维度 | Subjective Mind | Sealed Archive |
|---|---|---|
| 内容 | 主观痕迹（可失真、可遗忘） | 经过认证的原始记录 |
| 存储形态 | 加密片段 | **加密原始数据** |
| 密钥 | 主观记忆密钥层级 | **独立 Archive 密钥层级**，禁止混用/派生 |
| 写入者 | 提交器（单一入口） | **Archive Writer（唯一）** |
| 可读性 | 经注意机制可回忆 | **Brain 永不读取**；仅管理员审计另行授权 |
| 保留策略 | 遗忘事务（epoch + 墓碑） | **独立保留与删除策略** |
| 能否进入主观记忆 | — | **不能**；只能作为新观察从 Ingress 重新进入 |

**归档范围与完整性宣称**

- 采用**完整归档模式**：归档对象是"通过 Ingress 鉴权与校验的全部刺激"，**与注意判定和编码决定解耦**。
- 因此可以宣称"对已认证输入具备完整审计"。
- **若将来改为选择性归档**（例如只归档被注意的部分），必须同时：写明选择规则、在 API/UI/文档中
  取消"完整审计"表述、并在验收矩阵中降低相应承诺。**不得**在选择性归档下继续宣称完整审计。

**写入幂等**

- Archive Writer 按 `eventId` 幂等；同一事件重复请求不得产生第二条归档记录。
- 崩溃窗口（Archive 已写、`events.archive_ref` 未提交）由恢复流程按 `eventId` **查询后补标记**，
  不重写原文、不伪造记录。详见 `RUNTIME-LIFECYCLE.md` §7.3。

## 6. 原始正文的唯一进入路径

原始输入正文**只能**通过**短暂感知缓冲（TTL）**进入当前认知流程。除该缓冲与其后的编码结果外，
**不得**在任何一个长期存储位置留下原文副本。

具体禁止与流转规则见 `RUNTIME-LIFECYCLE.md` §7.1；字段级约束见 `DATA-MODEL.md` §3.1。

**可测试判据**：向系统注入带唯一标记串的刺激，遍历所有库表、索引、检查点与缓存，
该标记**只能**出现在允许的位置（感知缓冲的临时区、或已编码的主观记忆密文片段），
**不得**出现在 `events` 正文列、`tasks.payload_json`、`runtime_state.checkpoint_json` 或日志中。

## 6. 数据库与 Markdown 的权威关系

- **数据库是权威来源。**
- `SOUL.md` / `IDENTITY.md` / `MEMORY.md` 等 Markdown 是**版本化投影**：
  外部编辑后必须经 Schema、版本、权限校验才能导入。
- **禁止双主写入**：不允许文件和数据库同时作为权威。
- 人格可自行修改的内容（自我叙事、偏好）与永不允许人格修改的系统授权（密钥、授权策略）必须分离存放。

## 8. 明确允许与明确禁止

**允许**

- 主观记忆变形、细节遗失、来源误判、人物混合、时间错置、完整虚假自传体。
- 虚假主观记忆影响模拟情绪与关系。
- 用户提供新现实信息，作为**新观察**影响后续理解（这不叫"恢复记忆"）。
- 管理员按隐私策略清理 Archive（但不得因此改写主观叙述）。

**禁止**

- 用 Archive 作为"隐藏正确答案"去纠正或重建主观记忆。
- 用主观确信度授权任何现实动作。
- 向用户虚构操作结果、聊天证据、财务记录或现实人物的事实。
- 为通过测试而删除安全约束，或用 Mock 结果冒充真实功能。
- 在梦境中执行真实动作或外发消息。

## 10. 真实遗忘的存储约束

遗忘的事务流程见 `RUNTIME-LIFECYCLE.md` / `DATA-MODEL.md`。本节只规定**哪些存储位置必须被覆盖**，
以及**哪些位置天然会泄露**。

### 10.1 必须清理的位置

| 位置 | 风险 | 必须做的事 |
|---|---|---|
| 主观正文（加密列） | 密钥仍在即可解 | 删除密文 + **销毁对应内容密钥** |
| 片段表 | 同上 | 逐片段删除并销毁密钥 |
| 关系边 | 边端点已删但边仍可推断 | 删除所有以该节点为端点的边 |
| **FTS 索引** | **默认明文**，删了正文仍能搜到 | 见 10.2，必须专门处理 |
| 向量索引 | 向量可反向推断语义 | 删除对应条目并重建分片 |
| 内存缓存 / 激活状态 | 进程内残留 | 失效缓存、清除活跃子图条目 |
| 思维快照 / 检查点 | 可能含被引用内容 | 删除相关线程状态；检查点不得含正文 |
| 梦境输入 | 已删记忆仍可能被梦引用 | 睡眠/梦境任务启动前按 epoch 重校验可见性 |
| 历史修订 | 旧版本行 | 不保留可读历史修订，或修订本身加密 |
| 可读快照 / 导出 | 明文副本 | 导出物必须临时且受控删除 |
| 备份 | 可恢复旧内容 | 只存密文；密钥状态单独受控，不得随备份一起还原 |

### 10.2 FTS 的明文问题（未完全解决，见 OPEN）

SQLite FTS5 索引内容默认是**明文**，`node:sqlite` 无法对索引加密。这意味着"删除正文却保留索引"会直接泄露。

当前决议（P3 前必须定稿）：

- FTS 只索引**允许长期存在**的内容；可遗忘内容**不得**进入常驻 FTS。
- 可遗忘内容的检索走"**临时重建**"：按需从解密后的正文构建内存索引，用完即弃。
- 或改为只索引**主题标签 / 概念 ID**，不索引原文片段。

> 这是一条 **OPEN** 项：需要 P3 做基准测试后定案。在定案前，不得实现"常驻明文 FTS + 可遗忘内容"的组合。

### 10.3 WAL 与 secure_delete

- 删除行不等于从磁盘抹除。必须开启 `PRAGMA secure_delete = ON`，或对敏感内容永远只存密文。
- WAL 会保留旧页：遗忘事务完成后必须执行 `PRAGMA wal_checkpoint(TRUNCATE)`。
- 删除后必须做一次物理验证：在库文件与 `-wal` 中搜索金丝雀，命中数必须为 0。

### 10.4 备份

- 备份只保存**密文**与必要的元数据；内容密钥的状态独立管理，**不得**与备份放在一起。
- 恢复时若某批次的密钥已被销毁，则该批内容恢复后**不可解密**，且不得因此回退墓碑或 epoch。
- 恢复后必须跑一次金丝雀检查：已遗忘内容不得因恢复而重新出现。
