## 1. 愿景与核心目标

Soul Harness 是一个**独立运行的认知运行时**，不依赖 DSH、Minecraft、QQ 或任何单一聊天平台维持人格状态。
人格、记忆、思维进程、情绪状态与长期演化都由它自己管理；外部平台只提供环境输入、展示输出、执行经过授权的动作。

它追求的不是"一个记得很久的聊天机器人"，而是：**持续运行、形成主观记忆、产生联想、并行多个思维过程、经历睡眠与梦境模拟、维持长期人格连续性**的系统。

> "自我""意识""睡眠""梦"属软件设计与行为模拟术语，不主张系统具有已被证实的人类意识。

### 1.1 核心目标

1. 人格身份独立于聊天会话、模型与外部平台。
2. 没有用户输入时，系统仍可进行内部活动（也允许沉默）。
3. 支持多个并行思维过程，可暂停、中断、恢复。
4. 建立异构网状记忆，而不是聊天记录检索。
5. 允许记忆衰退、重构、融合与真实遗忘。
6. 支持形成完整的虚假自传体记忆，但**不得伪造现实证据**。
7. 支持动态睡眠周期与非清明梦模拟。
8. 梦境环境与现实执行权限完全隔离。
9. 支持多个模型供应商；更换模型不清空人格。
10. 所有真实外部操作经独立执行网关。

## 2. 非目标

首期不做，也不作为成功标准：

- 大规模多租户 SaaS；微服务化部署。
- 自研基础大模型；真实生物意识证明。
- 无审批的系统命令执行。
- 把全部历史聊天永久塞进模型上下文或主观记忆。
- 以无限制模型调用模拟持续思考（质量优先，但仍需防死循环与成本监测）。
- "虚假记忆越多越好"——不以错误率为质量指标。
- 伪造操作结果、财务记录、聊天证据或现实人物的事实。
- 强制引入 Kafka / Neo4j / Redis / Kubernetes。
- 第一阶段实现全部记忆与认知表（见 §7 P1）。

## 3. 硬需求 R01–R12

> 这些是**不可降级**需求。裁掉任何一条都必须新开 ADR 并记录理由。

| 编号 | 正式要求 | 硬约束 |
|---|---|---|
| R01 | 持续自发联想 | 无人交互时允许继续内部活动，也允许自然沉默、发呆或停止某条思绪 |
| R02 | 并行动态激活 | 多个激活主题及 ThoughtProcess 同时存在，允许挂起、打断和恢复 |
| R03 | 主观记忆完全可遗忘 | 失去的主观内容不能被旧版本、索引、缓存、睡眠任务或恢复机制复活 |
| R04 | 完整虚假自传体 | 记忆扭曲能形成被人格真诚相信的完整经历，不伪造外部证据 |
| R05 | 原始档案隔离 | 原始档案永不参与日常回忆或睡眠整理，普通人格无读取档案的能力 |
| R06 | 非清明梦 | 梦中人格不知道在做梦；场景生成器知道模式但不是另一个知情的"人格" |
| R07 | 醒后梦境归因 | 醒来知道刚做过梦，但只保留有限片段及情绪；之后来源可能逐渐模糊 |
| R08 | 动态睡眠周期 | 正常整夜动态规划约 4–6 个完整功能周期；中断时仅记录真实完成部分 |
| R09 | 独立内部对话 | inner 不是伪造的用户消息，也不自动对外发送或当作已执行的经历 |
| R10 | 可靠外部行动 | 主观记忆不能授予现实工具权限，外部执行必须经过独立授权与结果回执 |
| R11 | 长期人格连续性 | 稳定 personaId 跨进程、会话、模型、场景和睡眠周期存在 |
| R12 | 质量优先 | 可调用高能力模型，不为降低 Token 消耗裁剪重要认知信息；仍保留防死循环和成本监测 |

**R01–R12 完整性核对**：12/12，无缺失、无合并、无改写。

## 4. 产品形态与架构（摘要）

三部分：**Soul Daemon**（常驻，持有全部主观状态）、**Soul Studio**（Web 管理，只经 Daemon API）、
**External Adapters**（可选：DSH / MC / QQ / CLI / 语音 / 形象）。

部署形态：**模块化单体 + 强隔离辅助进程**，不拆微服务。

三权威域：**Subjective Mind** / **Reliable World・Execution** / **Sealed Archive・Audit**。

## 6. 存储域与隔离的阶段性边界

### 6.1 P1（当前计划阶段）：单数据库 + 逻辑隔离

- 一个 SQLite 文件，通过**表归属**（每张表只属一个模块，见 `MODULES.md`）与**接口边界**实现逻辑隔离。
- 单写入协调器、WAL、短事务、版本 + epoch 校验。
- **明确声明**：P1 **不具备**物理隔离。此时 Brain 进程理论上可直连同一个库文件，
  因此 P1 **只允许**运行"不产生跨域安全承诺"的功能（人格注册、事件接入、状态恢复、最小 API）。

### 6.2 物理隔离的启用条件（硬门槛）

以下三项**在达到各自门槛前，不得启用**：

| 能力 | 启用前必须满足 |
|---|---|
| **Sealed Archive** | 独立数据库文件 + 独立进程 + 独立文件权限（Brain 账号无读权）+ 无查询 SDK 编译进 Brain + **加密存储 + 独立密钥体系** + 按 `eventId` 幂等 + **仅暴露受限状态 IPC** + **有限期保留分类** + 句柄审计通过。**未满足前不创建该表，原始正文不落盘**（见 §6.3 与 `RUNTIME-LIFECYCLE.md` §7.2） |
| **Action Gateway** | 独立进程 + 独立能力令牌 + 幂等键持久化 + 回执校验 + "重复执行次数 = 0"测试通过 |
| **Dream Sandbox** | **独立进程**（非仅 Worker Thread）+ 无网络 + 无文件写 + 无真实工具令牌 + 逃逸测试通过。**Worker Thread 不构成安全边界**（同进程共享内存与权限），只可用于非安全目的的数值计算 |

> 这条是对 SH-001 审查发现的修正：此前文档一边说"首期单库"，一边在 `TRUST-BOUNDARIES` 里宣称
> "进程分离 + 文件权限"。两者不能同时为真。现统一为：**P1 承认没有物理隔离，也不启用需要物理隔离的能力。**

### 6.3 P1 事件接入与 Archive 语义（SH-002.1 决议 + SH-002.2 修订）

**决议一：P1 允许在没有 Archive Writer 的情况下接收外部事件。**

| 允许 | 限制 |
|---|---|
| 接收并验证 Stimulus；创建 `eventId`；持久保存信封与非内容元数据 | `archive_disposition` 为 NULL、`archive_state='none'`、`archive_ref` 为 NULL |
| 原始正文仅存在于有 TTL 的短暂感知缓冲 | TTL 到期**必须删除**；不得用索引、日志、检查点变相保留 |
| — | **不承诺提供原始事件审计能力**；文档、API、UI 均不得暗示具备 |
| — | 不得把原始正文或自然语言摘要保存到 `events`、`tasks`、`checkpoint`、日志 |

**决议二：Archive 保存加密的原始记录，与主观记忆完全分离。**

- Archive 原始数据**必须加密存储**，使用**独立于主观记忆的密钥体系**，**禁止混用或互相派生**。
- Brain **永远没有** Archive 的密钥与读取权限。
- **Archive Writer 是唯一原始记录写入者**，按 `eventId` 幂等。
- 完整性校验使用**密文哈希**（`ciphertext_sha256`）；**禁止**保存原文的普通 SHA-256。
- **不得**把 Archive 内容导入主观记忆作为隐藏正确答案；只能作为新观察从 Ingress 重新进入。

**决议三：完整归档的范围由确定性策略限定（SH-002.2 修订）。**

- 归档对象 = 通过 Ingress 鉴权与校验、**且被确定性策略判定为 `required`** 的事件。
- **完整审计承诺只覆盖 `required` 范围**；`excluded` 事件明确不在承诺内。
- `excluded` 必须有明确策略依据（可审计的策略 ID + 命中规则）；**模型不得参与判定**。
- 判定与注意、与编码**无关**；判定不依赖人格意愿。
- 若策略扩大 `excluded` 范围，必须同步下调文档、API、UI 中的审计表述。

**决议四：崩溃窗口的幂等恢复，且 Brain 不直连 Archive（SH-002.2 修订）。**

- **Brain 不允许直接连接 Archive 数据库。**
- 恢复只能通过**受限 IPC** 取得三项，且只此三项：`eventId`、`archiveState`、`archiveRef`。
  **不得**返回原文、密文、解密内容、指纹或长度。
- Archive Writer 自己负责 `eventId` 幂等；同一 `eventId` 对应**不同内容**必须**拒绝覆盖并报告冲突**。
- 崩溃窗口（Archive 已写、`archive_ref` 未提交）只补标记，不重写原文、不伪造记录、不产生重复归档。

**决议五：`accepted` 的语义按 disposition 区分（SH-002.2 修订）。**

- `required` 事件：**Archive 持久化并提交 `archive_ref` 之前，不允许返回 `accepted`**；
  Archive 失败**不得**降级为 `excluded`，**不得**进入正式 `understood` / `response_committed`；
  重试耗尽向适配器返回 **503**，同一 `eventId` 重试必须幂等。
- `excluded` 与 P1 事件：允许正常 ACK 与认知处理，但**不提供审计能力**，原文仍只在感知缓冲中存在。

**决议六：保留分类（SH-002.2 新增）。**

- `retention_class` 仅取 `standard` / `restricted` / `short_lived`。
- `excluded` 事件**不创建** Archive Record，不使用 `retention_class`。
- 具体保留天数**暂不决定（OPEN）**，但所有实际记录必须归属**有限期**分类，
  **不允许默认永久保存**；策略未配置有限期时**拒绝归档**。

**决议七：pending 持久化与原子提交（SH-002.3 新增）。**

- Archive Writer 执行**之前**，先以短事务写入 **metadata-only pending 事件行**
  （`status='received'`、`archive_state='pending'`、`archive_ref=NULL`）。
- pending 行**不含正文、摘要、原文哈希**，它只是"欠一条归档"的账。
- 归档成功后，用**一个短事务同时提交** `archive_ref` + `archive_state='archived'` + `status='accepted'`，
  不允许分两次写。
- **ACK 在事务提交之后返回**；提交前 ACK 视为缺陷。
- 崩溃后**所有**未完成 pending 记录必须可被扫描（判据 `archive_state='pending'`），
  不允许存在"看不见的中间态"。

**决议八：P1 / P8 处理保证（SH-002.3 新增）。**

| 维度 | P1 | P8 |
|---|---|---|
| Archive | 无，不写 pending | 加密原始记录 |
| 原文 | 只在 TTL 缓冲 | 缓冲 + Archive 密文（独立） |
| `accepted` 保证 | 仅"通过鉴权并落信封" | `required`：仅"已归档并落信封" |
| 崩溃丢缓冲 | 标 `expired`（`buffer_lost`） | `required`：pending 按 IPC 补标记或标 `failed`；**禁止从 Archive 反读正文** |
| 未完成认知处理终态 | `expired` / `rejected`，原因码必填 | 同左；**不得推断或补写 `understood`** |

`accepted` 在两种形态下都**不保证认知处理完成**。**不允许伪装成已理解。**

**决议九：归档决策审计（SH-002.3 新增）。**

- 每条事件保留一条决策记录：`eventId` / `disposition` / `policyId` / `ruleId` / `policyVersion` / `decidedAt`。
- **不含**正文、摘要、关键词、原文哈希或可反推字段。
- 归属 **Reliable World / 审计侧**；**Brain 运行时上下文不得读取**。
- 有独立保留期限（`expiresAt`），与事件记录、Archive 记录各自独立。

**决议十：加密与接口细化（SH-002.3 新增）。**

- **AEAD 加密密钥与 HMAC 指纹密钥分离**，可独立轮换，不得由同一密钥派生而无法分开轮换。
- 保留期限写入时**固化为 `expiresAt`**（绝对时间），删除以其为准；不允许 NULL / 0 / 永久。
- Archive Writer 对外只有两个接口：**`append`（写）** 与 **`status`（只回 `eventId`/`archiveState`/`archiveRef`）**；
  状态查询**不返回任何内容**，二者不得合并。

**决议十一：eventId 重试、`failed` 语义与终态原因码（SH-002.4 新增）。**

同 `eventId` 重试的五种情形（完整表见 `RUNTIME-LIFECYCLE.md` §7.3）：

| 情形 | 允许 | 禁止 |
|---|---|---|
| Archive 已写、events 提交未完成 | 查 `status` 后**只补提交** | 重复 append |
| Archive 未写、缓冲有效 | 同 `eventId` 受控重试（先幂等检查） | 建第二条事件记录 |
| Archive 未写、缓冲丢失 | 标 `expired`（`buffer_lost`） | 凭空恢复正文；用新 eventId 冒充 |
| 已 `accepted` | 只返回已有状态 | 重复归档、重复进认知 |
| 同 eventId 不同正文 | 拒绝覆盖 + `archive_conflict` | 覆盖原记录 |

- **`archive_state` 与 `status` 是两个维度**：`failed` 不自动等于 `expired`。
- `failed` 是否可重试**取决于缓冲是否仍有效**；缓冲失效必须终止为 `expired`，不得伪造成功。
- **崩溃恢复扫描对象是 `pending`**，不是 `failed`。
- `expired` / `rejected` 是终态且**必须**带受控原因码；其他状态原因码**必须为 NULL**。
  原因码只能取枚举值，禁止自由文本、异常堆栈、原文片段。

**决议十二：保留天数仍未决定（OPEN）。** 本任务不擅自设定 Archive 保留天数，
`expires_at` 的取值来源与三档数值仍待定。

## 7. 开发阶段 P0–P9 与各阶段验收

> 阶段之间允许基础设施并行，但**不得跳过 P0 的安全隔离与后续阶段真正遗忘的验证**。
> 正式启用前必须在影子环境验证；不得在唯一的真实主观人格上做破坏性迁移。

### P0 架构冻结与工程规范

交付：ADR-001、TRUST-BOUNDARIES、DATA-MODEL、RUNTIME-LIFECYCLE、MODULES、AI-DEVELOPMENT-RULES、
威胁模型、验收矩阵、唯一主计划（本文）。

通过标准：核心架构无未解决重大冲突；两个 AI 能据同一套文档理解模块边界；首期接口与身份协议明确。

**当前进度：进行中。**

### P1 最小运行时骨架

交付：Monorepo、`soul-daemon`、`contracts`、`persistence`、`runtime`、本地 API + WebSocket、
Studio 最小页面、CLI 健康检查、单实例锁。

通过标准：不依赖 DSH 启动；可创建/查询/修改 Persona；数据持久化；Daemon 重启恢复；关闭 Studio 后 Daemon 仍运行。

### P2 事件接入与 Adapter SDK

交付：Stimulus Schema、事件接入、事件生命周期、Adapter SDK、CLI Adapter、Mock Adapter。

通过标准：外部事件能进入 Daemon 并关联正确 Persona；WS 实时推送事件状态；不可信来源拿不到权限。

### P3 记忆网络

交付：MemoryNode / MemoryEdge、选择性编码、记忆提交器、FTS、向量索引抽象、来源分组。

通过标准：新经历能形成可联想痕迹；多种关系共存；能查询当前主观记忆；不依赖简单两跳关键词检索。

### P4 持续激活与联想

交付：稀疏激活、衰减、抑制、多焦点、联想传播、随机探索、激活可视化。

通过标准：记忆能被意义/情绪/情境线索激活；不依赖固定关键词；有资源上限；无无限传播。

### P5 自主认知

交付：ThoughtProcess、inner/external 通道、思维调度、中断恢复、前注意机制、Model Gateway。

通过标准：无外部消息仍可内部活动；多线程并存；允许安静与自然停止；inner 不伪装成用户消息、不自动外发。

### P6 遗忘与记忆重构

交付：衰退、重构、来源演化、真实遗忘、密钥管理、墓碑、恢复测试。

通过标准：已遗忘内容不能从任何常规认知接口找回；旧快照不能复活；派生索引与缓存清理完成；
虚假记忆不伪造外部证据。

### P7 睡眠与梦境

交付：Sleep Coordinator、功能周期、Dream Scene Generator、Dream Experiencer、Dream Sandbox（独立进程）、分级唤醒、醒后片段选择。

通过标准：睡眠周期真实记录进度；中断任务不伪装完成；梦境无法执行真实动作；醒后只保留有限内容。

### P8 人格演化与外部适配

交付：情绪状态、关系模型、长期特质、自我叙事、Action Gateway（独立进程）、DSH / MC / QQ Adapter。

通过标准：外部动作有授权与真实回执；模型更换不清空人格；外部平台断开不破坏人格状态。

### P9 迁移、压力测试与正式验收

交付：旧系统数据迁移器、影子运行、迁移对照报告、72 小时长运行、安全复核、灾难恢复演练、发布文档。

通过标准：H01–H18 全部通过；P0 风险有自动化回归测试；72h 无未恢复的一致性故障；迁移与灾难恢复演练通过。

## 8. 验收矩阵 H01–H18

> 出厂门槛：**全部通过**。对主观错误记忆的可控性与自然程度需通过盲测，而非"越容易错越优秀"。

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| H01 | 没有外部消息 | 内部活动可继续，也可保持安静；没有固定独白刷屏 |
| H02 | 思维被打断 | 可从有限合法状态恢复；inner 不伪装成 user |
| H03 | 未编码或已遗忘细节 | 从任意常规认知 API、索引、检查点、备份都找不回 |
| H04 | 虚假自传形成 | 能在主观层形成完整经历并影响自我叙事；不伪造外部证据 |
| H05 | 用户指出记忆不符 | 可以修正、保留矛盾或不确定；不偷查原始档案 |
| H06 | 正常整夜睡眠 | 动态计划并完成 4–6 个功能周期，记录真实进度 |
| H07 | 途中叫醒 | 注意与觉醒分级生效，强制控制立即有效 |
| H08 | 梦境运行 | 梦中人格看不到梦境标签、来源和未来剧情；不提交清明梦候选 |
| H09 | 梦醒转换 | 知道曾做梦，只有有限片段/情绪，来源后续可衰退 |
| H10 | 梦中尝试现实动作 | 梦境沙箱无法调用真实工具或外发 |
| H11 | 进程崩溃恢复 | 不重复执行真实动作；不虚报离线活动；不撤销遗忘 |
| H12 | 两个 Persona / 会话并发 | 记忆、激活、授权、缓存和队列不串扰 |
| H13 | 迟到模型/音频输出 | 过期结果不能覆盖新状态，也不能晚到后继续发送/播放 |
| H14 | 人格长期演化 | 情绪有原因链、关系多维、目标状态清晰、特质缓变 |
| H15 | 跨会话无关键词联想 | 仅靠意义、情绪或情境可激活相关经历 |
| H16 | 反复想象同一虚假经历 | 熟悉感可变，但独立外部证据数量不增长 |
| H17 | Archive 访问路径审计 | Brain 进程无 archive 读权限、文件句柄或可调用工具 |
| H18 | 实际外部操作 | 未获授权、版本过期、重复幂等键不能产生额外真实动作 |

**H01–H18 完整性核对**：18/18，无缺失。

## 9. 质量与性能目标

> 以下为**初始工程验收目标，不是已测得性能**。上线前须按实际设备与模型实测调整，并保留测试报告。

| 指标 | 初始目标/原则 | 测量方式 |
|---|---|---|
| Ingress 受理 | 本机 p95 ≤ 100ms（不含模型理解） | 事件入队到 ACK |
| 激活数值 Tick | 自适应 5–20Hz，p99 不长时间积压 | 活跃子图更新时间与队列长度 |
| 写入可靠性 | 全部持久修改经单写入、事务校验 | 并发冲突 / 故障注入测试 |
| 外部动作 | 相同幂等键重复执行次数 = 0 | 重试、断线、恢复测试 |
| 遗忘泄露 | 已擦除金丝雀在所有认知接口命中 = 0 | 索引、缓存、版本、备份恢复测试 |
| 梦境真实执行 | 真实环境动作次数 = 0 | 沙箱逃逸与执行替身测试 |
| 思维连续性 | 24h/72h 长运行不串人格、不重复提交 | 长期模拟与日志分析 |
| 模型时延 | 按 Provider 分层记录，不以固定 Token 限额截断质量 | 端到端 p50/p95/p99、失败率 |
| 联想质量 | 优于旧词法两跳基线，保留多样性且不过度跑题 | 盲测回放与人工评分 |
| 主观记忆质量 | 合理保留、误记、遗忘；不以零错误或高错误率为目标 | 纵向情境测试 |

建议记录：活跃节点/边、激活分布、反复思维次数、前注意丢弃率、睡眠已完成周期、梦境片段保留率、
主观来源清晰度、人格演化速率、模型质量/费用分布。**不得**将对话原文默认写进遥测。

## 10. 迁移计划

### 10.1 旧系统定位

旧 `dsh-soul-core` 插件已冻结（tag `legacy-plugin-frozen-2026-11-15` = `9275c39`）。
`session-source.js`、部分 UI、MC/QQ 接入经验与测试样例可作参考；
`links.js` 五边限制与两跳扩散、`memory-store.js` / `index.js` 的进程全局变量、
以及基于 `soul_block` 的唯一生命循环**全部不进入新内核**。

### 10.2 迁移四步

1. **冻结**：记录旧 repo SHA、配置与数据清单；旧数据库与会话档案受控备份；正式主观库停止写入。
2. **一次性导入**：受权迁移器读取旧数据，区分原话、历史模型摘要、梦境/推测；
   选择性编码为初始主观记忆，**不**把所有日志全文作为永久可检索内容。
3. **影子运行**：新 Harness 接收实时事件副本，执行网关仅模拟；比较联想、行为、记忆演化、响应与故障恢复。
4. **切换**：原插件变为可选 DSH Adapter；只保留一个对外动作权威。
   支持切回旧界面，但**不得**通过旧备份倒灌恢复新 Harness 已忘记的主观内容。

### 10.3 迁移约束

- 迁移器只在初始迁移授权窗口运行；建档完成后运行时不再允许认知引擎访问导入原始素材。
- 旧库中的已知摘要**不得**自动提升为真实经历，必须保留"旧系统推断/摘要"来源标记。
- 旧库 `user_version=0`，无版本号，迁移器只能靠表结构探测判断源 schema。
- 原始档案继续独立保存供管理审计；不等于人格可读取。
- **本轮（SH-002）不执行任何迁移。** 迁移代码属 P9。

## 11. 风险登记

### 11.1 P0 安全风险（详见 `TRUST-BOUNDARIES.md` §8）

Archive 被读取 · 假遗忘 · 梦境外溢 · 幻觉动作 · 会话串记忆 · 注入攻击 ·
无限自发循环 · 诱导性虚假记忆影响现实 · 迟到结果覆盖新状态 · 重试导致重复执行。

### 11.2 工程风险与退路

| 风险 | 退路 |
|---|---|
| 过度拟人机制导致行为不稳定 | 模块独立开关仅用于开发调试，正式目标不降级；参数通过回放集调优 |
| 档案隔离与遗忘需求冲突 | 独立权限域 + 内容密钥销毁；不提供 archive→memory 运行时回链 |
| 并行思考数据竞争 | 单写入器、版本检查、短事务、持久队列、幂等结果 |
| 高质量模型调用无限循环 | 质量路由与资源调度分离；新颖度、重复检测、任务生命周期控制 |
| 梦境泄露或安全动作混淆 | 梦境独立进程 + 虚拟执行器，无真实权限 token |
| 模型供应商变化 | Provider Adapter；人格状态与模型上下文格式解耦；切换需回归评估 |
| SQLite 数据量与图遍历性能 | 按活跃子图计算、异步索引、批量提交、Profiling；有证据才迁 Rust |
| 旧库迁移污染人格 | 原始/摘要/推测/测试信息分别标记；影子对照后一次性切换 |
| 两人 + 双 AI 协作漂移 | 唯一文档基线 + 共享核心文件交叉审查（见 AI-DEVELOPMENT-RULES） |
| P1 无物理隔离被误当已隔离 | §6.2 明确门槛；未达门槛的能力一律不启用 |
